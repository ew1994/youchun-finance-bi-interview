## 1. 需求背景

### 1.1 岗位问题

财务 BP 需要把分散在销售、生产、库存、费用和资金数据中的信息整理成月度经营结论。重复的数据整理、指标计算、异常下钻和报告撰写，容易造成：

- 数据口径不一致，GMV、收入、结算和回款混用。
- 只看收入和毛利，无法解释渠道费用、报损和公共费用后的真实贡献。
- 只看利润，无法解释应收、库存和应付对现金的影响。
- 看板、Excel 和报告分别计算，复核困难，交付时效不可衡量。

### 1.2 业务背景

公开信息显示，悠纯具有乳品生产、多温层产品、多渠道、自有品牌、OEM 和区域市场等特征。分析必须体现：

- 常温与低温产品的库存、冷链和报损差异。
- 电商、经销、商超、私域、OEM 等渠道的净价、费用和账期差异。
- 材料、人工、制造费用和单位生产成本对毛利的影响。
- 应收、库存和付款安排对经营现金的影响。

### 1.3 现有数据基础

项目已生成 18 个 Mock Excel 工作簿，覆盖采购、生产、销售、出库、售后、库存、费用、应收应付、现金、预测和行动项，并通过生成器 13 项及独立复核 19 项检查。

PRD 不再要求“先准备数据”，而是要求看板正确消费现有原始数据。

## 2. 产品目标与成功标准

### 2.1 产品目标

1. 用同一套数据与指标口径输出月度经营、单品盈利、生产成本与库存、费用、现金流五类分析。
2. 支持从公司到区域、渠道、SKU 和原始批次的下钻，解释异常原因候选。
3. 将异常转化为措施、责任角色、完成期限和复检指标。
4. 从同一指标结果生成月度经营、单品盈利、费用和现金流四类专项报告。
5. 用自动勾稽和金标准样例证明计算正确，而不是只证明页面能显示。
6. 建立同范围交付工时测量方法，以企业实测验证报表交付时效提升 50% 以上。

### 2.2 成功标准

| 维度 | 验收标准 |
|---|---|
| 分析完整性 | 九个页面均可访问，前置说明、经营分析、专项报告和技术验证均能按顺序演示 |
| 口径一致性 | 页面、SQL、导出和报告使用同一指标结果 |
| 数据正确性 | 净收入、毛利、贡献利润、库存、应收应付和现金校验全部通过 |
| 异常可解释性 | 六组内置异常均可下钻到原始证据并形成行动 |
| 可演示性 | 本地启动，默认 6 分钟内能够完成核心故事演示 |
| 交付效率 | 企业同范围实测平均交付工时下降不低于 50%，且无新增重大口径错误 |

“提升 50%”是 JD 目标，不是 Mock 项目已经实现的企业业绩。

## 5. 数据源与数据模型

### 5.1 数据源清单

| 数据域 | 原始文件 | 最小粒度 | 主要用途 |
|---|---|---|---|
| 产品 | `D_产品主数据.xlsx` | 一个 SKU | 品牌、品类、温层、规格、保质期和基准成本 |
| 渠道区域 | `D_渠道区域客户主数据.xlsx` | 渠道×区域 | 客户类型、渠道和账期 |
| 工厂供应商 | `D_工厂供应商主数据.xlsx` | 一个工厂/供应商 | 名义产能、材料和付款账期 |
| 采购 | `F_采购订单.xlsx` | 月×工厂×原材料 | 采购价格、数量、到货和应付新增 |
| 生产 | `F_原材料出库及生产成本宽表.xlsx` | 月×工厂×SKU | 材料、人工、制造费用和产量 |
| 销售 | `F_销售订单汇总表.xlsx` | 月×区域×渠道×SKU | 收入、折让、退款、销量和订单数 |
| 出库 | `F_产成品销售出库表.xlsx` | 一个销售汇总批次 | 出库数量和实际成本 |
| 售后 | `F_售后退款表.xlsx` | 一个销售汇总批次 | 退款、退货和可售成本冲回 |
| 库存 | `F_产成品库存批次.xlsx` | 月×工厂×SKU | 库存勾稽、临期和报损 |
| 直接费用 | `F_渠道费用表.xlsx` | 销售批次×费用类型 | 履约、渠道、推广和达人费用 |
| 公共费用 | `F_期间费用与预算.xlsx` | 月×部门×科目 | 公共费用实际和预算 |
| 应收应付 | `F_应收应付核销.xlsx` | 月×客户/供应商 | 新增、收付、期末和账龄 |
| 现金 | `F_银行现金流水.xlsx` | 月×资金类别 | 经营收付和现金余额 |
| 预测 | `F_现金流预测.xlsx` | 周×情景 | 13 周现金预测和安全线 |
| 新厂情景 | `F_金昌投产情景.xlsx` | 月×情景 | 产能爬坡、营运资金和资本开支 |
| 行动 | `F_经营行动项.xlsx` | 一项异常行动 | 原因、措施、责任人和复检 |

销售一行是财务汇总，不是消费者订单；订单数字段是该汇总组合的订单总数。

### 5.2 数据模型与连接键

```text
产品/渠道/区域/工厂主数据
          ↓
销售汇总批次 ─→ 售后退款
     ↓
销售出库 ← 生产批次 → 库存批次
     ↓              ↓
渠道费用          采购订单 → 应付核销
     ↓                            ↓
贡献利润 ← 公共期间费用   应收核销
     ↓                            ↓
     └──── 管理经营利润与经营现金 ────┘
```

- `SKU编码`：连接产品、销售、生产、出库、售后、库存和费用。
- `销售汇总批次号`：连接销售、出库、售后和渠道费用。
- `生产批次号`：连接生产成本和库存。
- `客户/供应商编码`：连接销售/采购和应收应付。
- `月份`：统一为 `YYYY-MM`，所有事实表必须具备。
- `费用属性`：直接费用进入贡献利润，公共费用在公司层扣除。

### 5.3 数据处理原则

- 先按连接键预聚合，再连接，避免渠道费用多行造成收入重复。
- 所有页面使用同一指标层，不在前端分别重算财务指标。
- 金额保留两位小数，比率使用统一精度；零分母显示 `—`。
- 所有原始记录和输出保留 `MOCK` 标识。

## 6. 指标与计算规则

### 6.1 销售与对比

| 指标 | 公式 | 说明 |
|---|---|---|
| 管理净销售收入 | 确认销售收入－销售折让－成功退款 | 不含税经营管理口径 |
| 有效销量 | 销售数量－退款数量－无效数量 | 与净收入匹配 |
| 平均净售价 | 管理净销售收入÷有效销量 | 同时受价格与结构影响 |
| 同比增长率 |（本期－去年同期）÷去年同期 | 观察年度增长 |
| 环比增长率 |（本期－上期）÷上期 | 观察短期变化 |
| 预算达成率 | 实际÷预算 | 用于收入等正向指标 |

### 6.2 毛利与贡献

| 指标 | 公式 | 说明 |
|---|---|---|
| 销售成本 | 出库实际成本－可售退货冲回成本 | 与本期净收入匹配 |
| 商品毛利 | 管理净销售收入－销售成本 | 产品层盈利 |
| 商品毛利率 | 商品毛利÷管理净销售收入 | 公司层必须为总毛利÷总收入 |
| 贡献利润 I | 商品毛利－变动履约－渠道交易－报损 | 扣直接经营成本 |
| 贡献利润 II | 贡献利润 I－直接推广－达人佣金 | 用于渠道和 SKU 主分析 |
| 管理经营利润 | 全公司贡献利润 II－公共期间费用 | 不称法定净利润 |

直接费用在费用页可重复展示其科目，但在利润计算中只能扣一次。

### 6.3 生产、库存和费用

| 指标 | 公式 | 说明 |
|---|---|---|
| 单位生产成本 | 总生产成本÷合格产量 | 按工厂、品类和月份分析 |
| DIO | 平均库存成本÷销售成本×期间天数 | 库存资金占用 |
| 报损金额率 | 报损成本÷（期初库存成本＋本期入库成本） | 库存损耗 |
| 临期库存占比 | 临期库存成本÷可售库存成本 | 风险不等于已报损 |
| 总期间费用 | 直接经营费用＋公共期间费用 | 与利润防重复扣减 |
| 总费用率 | 总期间费用÷管理净销售收入 | 费用相对收入负担 |
| 费用预算差异 | 实际费用－预算费用 | 正数通常表示超支 |

### 6.4 现金与营运资金

| 指标 | 公式 | 说明 |
|---|---|---|
| 销售回款 | 应收期初＋新增应收－应收期末 | 按实际收付口径 |
| 经营现金净流入 proxy | 经营现金流入－经营现金流出 | 不替代法定现金流量表 |
| DSO | 平均应收÷赊销收入×期间天数 | 应收占用时间 |
| DPO | 平均应付÷赊购金额×期间天数 | 应付账期 |
| CCC | DIO＋DSO－DPO | 现金转换周期 |
| 预测期末现金 | 期初现金＋预计流入－预计流出 | 13 周资金预警 |

## 7. 产品功能设计

### 7.1 全局功能

| 编号 | 功能 | 需求 | 验收 |
|---|---|---|---|
| G01 | 期间筛选 | 支持完整月份、季度和年度累计，默认 2026-09 | 切换后所有指标和报告同步 |
| G02 | 业务筛选 | 区域、渠道、品牌、品类、温层、SKU、工厂 | 筛选条件清晰且可重置 |
| G03 | 对比 | 同比、环比、预算差异 | 比率变化以个百分点展示 |
| G04 | 数据状态 | 显示 Mock、数据版本、更新时间和质量状态 | 每页可见，不可隐藏免责声明 |
| G05 | 导出 | 当前筛选明细、指标结果和报告 | 导出与页面一致 |

### 7.2 页面一：月度经营总览

**目标**：用最少信息判断本月结果和优先异常。

- KPI：管理净销售收入、商品毛利率、贡献利润 II、管理经营利润、总费用率、经营现金净流入。
- 图表：近 13 个月收入与毛利率、利润瀑布、渠道收入与贡献、区域经营表。
- 异常 Top 5：指标证据、影响金额、下钻目标、原因候选和待核实事项。
- 验收：默认月份能够呈现“收入增长、贡献下降、现金同比走弱”的 Mock 故事。

### 7.3 页面二：销售与单品盈利

**目标**：识别规模和贡献不匹配的区域、渠道与 SKU。

- KPI：净销售收入、有效销量、平均净售价、贡献利润率 II。
- 图表：区域收入及同比、渠道收入—贡献利润率、SKU 散点、净价与单位成本趋势、SKU 明细。
- 散点四象限：优势款、重点诊断款、潜力款、观察/精简款。
- 验收：能够定位抖音负贡献、天山奶啤负贡献及基础白奶高收入低贡献。

### 7.4 页面三：生产成本与库存

**目标**：解释成本、库存和报损对利润与现金的影响。

- KPI：单位生产成本、期末库存、DIO、报损金额率。
- 图表：成本结构、单位成本趋势、库存状态、库存周转与报损明细、产能利用率情景卡。
- 验收：基础白奶成本上升、重点低温 SKU 临期及报损能够回到生产和库存批次。

### 7.5 页面四：费用分析

**目标**：识别费用结构、预算偏差及渠道费用效率。

- KPI：总期间费用、总费用率、销售费用率、预算差异。
- 图表：费用结构、实际与预算、费用率趋势、部门差异、渠道直接费用率。
- 验收：直接和公共费用分列；渠道费用超支 54.09 万元的 Mock 证据可复核。

### 7.6 页面五：现金流与营运资金

**目标**：解释利润与现金差异并提前识别资金风险。

- KPI：销售回款、经营现金净流入、CCC、期末可用资金。
- 图表：月度现金收付、利润与经营现金、DIO/DSO/DPO、应收账龄、13 周预测。
- 验收：经营现金同比下降、OEM 账期和逾期、应收与库存增加均可下钻；金昌不混入历史。

### 7.7 页面六：专项报告与行动项

**目标**：把分析结果转成可复核的标准交付。

- 四类报告：月度经营、单品盈利、费用、现金流与营运资金。
- 固定结构：结论→证据→原因候选→措施→责任人→期限→复检指标→Mock 声明。
- 行动项支持状态：待核实、处理中、待复检、已关闭。
- 验收：报告数字与当前筛选一致，不允许无来源金额或确定性经营结论。

### 7.8 前置说明页与末尾技术页

**前置页：作品总览、假设与数据**

- 作品总览说明岗位需求、业务背景、分析范围、主线和交付边界。
- 假设与数据集中展示 A/B/C 三层依据、Mock 业务情景、18 个工作簿的连接关系和手算样例。
- 验收：面试官不打开其他文档，也能理解公开依据、模拟假设、数据来源和指标口径。

**末尾页：技术架构与代码**

- 展示 Python/pandas、SQLite、Streamlit/Plotly 的职责与数据流。
- 展示 SQL 防重复、Python 分层计算、13＋19 项校验以及源文件入口。
- 验收：能够说明输入、规则、结果和修改分别如何验证，不把技术实现包装成黑盒。

**统一导览要求**

- 00—08 页按顺序讲解，每页提供讲解提示和上一步/下一步。
- 独立导览 HTML 仅作为统一 BI 入口，不再维护两套内容。

## 8. 异常分析与行动闭环

本期内置六组 Mock 情景：

| 异常 | 主要证据 | 措施方向 |
|---|---|---|
| 增收不增利 | 收入同比增长、贡献利润率下降、抖音负贡献 | 分 SKU/活动核算贡献，调整投放 |
| 基础白奶成本上升 | 单位成本同比上升、采购价格上涨 | 比价、采购优化、促销净价复核 |
| 低温临期与报损 | 临期占比和报损金额率升高 | 滚动预测、先到期先出、调拨促销 |
| 渠道费用超预算 | 实际高于预算、销售费用率上升 | 复盘增量贡献，调整预算与投放 |
| OEM/KA 回款变慢 | DSO 和逾期应收上升 | 信用分层、验收前置、账龄责任到人 |
| 现金走弱与 CCC 变长 | 经营现金同比下降、应收和库存增加 | 催收、库存去化、付款协同和预测 |

异常原因均为候选，真实企业必须经业务核实后才能关闭。

## 9. 数据质量与评测

### 9.1 确定性校验

- 净收入＝确认收入－折让－成功退款。
- 销售出库数量与销售数量一致。
- 销售成本＝出库成本－可售退货冲回。
- 毛利、贡献利润和管理经营利润计算一致。
- 库存数量与成本期初、入出库、报损和期末勾稽。
- 应收应付期初、新增、核销和期末勾稽。
- 现金期初、经营净额、投资筹资净额和期末勾稽。
- 年度收入与 Mock 配置一致，SKU 外键完整，金昌不倒填历史。

### 9.2 分析评测

- 使用人工手算的金标准样例覆盖正常、退款、可售退货、零收入、负贡献和库存场景。
- 每次修改生成规则、SQL 或指标函数后重新运行校验。
- 页面、导出和报告对同一筛选条件进行一致性检查。
- AI 如用于报告，只能引用 SQL 结果和原始证据，不能自行生成金额。

## 10. 非功能需求

- 本地轻量运行，不依赖外部图表 CDN、在线 AI 或企业系统。
- 默认桌面分辨率 1366×768 以上，适配常见浏览器。
- 常规汇总查询目标 2 秒内返回，明细表分页。
- 视觉以清晰、克制、财务可读性为先，不用装饰替代信息。
- 所有 Mock 数据不含真实个人信息、账号、密钥或商业秘密。

## 11. 报表交付时效验收

```text
单次交付工时 = 数据准备 + 指标计算 + 异常说明 + 报告复核交付
交付时效提升率 =（基线平均工时－上线后平均工时）÷基线平均工时
```

- 从源数据齐备开始，到财务经理收到可复核月报结束，包含人工复核。
- 同范围至少记录三次基线和三个完整上线周期，同时记录平均值和最大值。
- 平均工时下降不低于 50%，且勾稽通过、无新增重大口径错误才判定达标。
- 面试作品只展示测量方法，不宣称悠纯已经实现。
